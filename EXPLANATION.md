# Як працює самостійна робота №2

## 1. Загальний принцип

Це односторінковий сайт виробника меблів «Затишок». React створює інтерфейс із компонентів, JSON зберігає дані, CSS відповідає за оформлення та адаптивність. Усі товари й компанія є навчальним прикладом.

Послідовність запуску: `index.html` → `main.jsx` → `App.jsx` → компоненти → HTML-елементи в браузері.

## 2. Файли проєкту

| Файл | Призначення |
| --- | --- |
| `index.html` | Початковий HTML із контейнером `root` |
| `src/main.jsx` | Підключає React, стилі та запускає застосунок |
| `src/App.jsx` | Об’єднує шапку, основний контент і футер |
| `src/components/Header.jsx` | Назва компанії та меню |
| `src/components/Products.jsx` | Картки меблів |
| `src/components/Footer.jsx` | Контакти та соцмережі |
| `src/data.json` | Тексти, меню, товари, ціни й посилання |
| `src/style.css` | Оформлення та правила для різних екранів |
| `public/images` | Локальні зображення меблів |
| `package.json` | Залежності та команди запуску |
| `package-lock.json` | Точні версії встановлених пакетів |

## 3. Точка входу main.jsx

```jsx
import React from 'react';
import { createRoot } from 'react-dom/client';
import App from './App';
import './style.css';

createRoot(document.getElementById('root')).render(<App />);
```

`import` підключає бібліотеки та файли. `getElementById('root')` знаходить контейнер із `index.html`. `createRoot` створює корінь React у цьому контейнері, а `render(<App />)` відображає головний компонент.

`<App />` — JSX. Це запис розмітки всередині JavaScript, який інструмент збірки перетворює на виклики React. Тому нам не потрібні ручні `createElement` та `appendChild`, як у першій самостійній.

## 4. Компоненти та App.jsx

Компонент — функція, яка повертає JSX. Назви компонентів починаються з великої літери, щоб React відрізняв їх від звичайних HTML-тегів.

`export default` дозволяє імпортувати компонент в інший файл.

`App` повертає таку структуру:

```jsx
<>
  <Header />
  <main className="container">
    {/* Блок про виробника */}
    <Products />
  </main>
  <Footer />
</>
```

`<>...</>` — фрагмент: він об’єднує елементи без зайвого `div`. `className` у JSX відповідає HTML-атрибуту `class`. Фігурні дужки вставляють у розмітку значення JavaScript, наприклад `{data.about.title}`.

Блок про виробника бере заголовок, опис, ілюстрацію та текст посилання з `data.about`. Посилання `href="#products"` прокручує сторінку до каталогу з `id="products"`.

## 5. Як читається JSON

```jsx
import data from './data.json';
```

Інструмент Vite читає JSON і дозволяє працювати з ним як з об’єктом JavaScript. Наприклад, `data.company` — назва компанії, `data.products` — масив товарів.

У компонентах із папки `components` використовується шлях `../data.json`: `..` означає перехід на один рівень вище.

Це статичний імпорт, а не окремий мережевий `fetch`. Під час збірки дані включаються в застосунок. Після зміни JSON для готової версії потрібно повторити збірку; під час розробки Vite оновлює сторінку.

Умова другої роботи вимагає JSON, але не обов’язково JSONBin. У прикладі методички JSON також зберігається поруч із компонентом, тому тут використано локальний файл. Після встановлення залежностей локальний сайт працює без інтернету; інтернет потрібен для переходу на соцмережі.

## 6. Header і створення меню

```jsx
{data.menu.map(item => (
  <a key={item.href} href={item.href}>{item.text}</a>
))}
```

`map` перебирає масив меню і повертає посилання для кожного запису. `item` — поточний пункт, `href` — адреса переходу, `text` — видимий текст.

`key` — унікальний ключ елемента списку. Він допомагає React зіставляти елементи під час оновлення інтерфейсу. Тут адреси пунктів різні, тому їх використано як ключі.

Меню веде до трьох блоків: `#about`, `#products`, `#contacts`. Нові сторінки при цьому не відкриваються. `aria-label` пояснює призначення навігації програмам читання з екрана.

Ефект наведення реалізує CSS:

```css
nav a:hover, nav a:focus-visible {
  background: #71533c;
  color: white;
}
```

`:hover` спрацьовує під курсором, `:focus-visible` — зокрема при переході клавішею Tab. Змінюються фон і колір тексту. JavaScript для цього не потрібен.

## 7. Products і картки меблів

Кожен товар у JSON має `id`, `name`, `type`, `description`, `price`, `image`.

```jsx
{data.products.map(product => (
  <article className="product" key={product.id}>
    <img src={product.image} alt={product.name} loading="lazy" />
    <div className="product-info">
      <p className="label">{product.type}</p>
      <h3>{product.name}</h3>
      <p>{product.description}</p>
      <p className="price">{product.price.toLocaleString('uk-UA')} грн</p>
    </div>
  </article>
))}
```

`map` створює три картки з трьох записів JSON. `key={product.id}` задає кожній картці стабільний унікальний ключ.

`src` указує зображення, `alt` описує його, а `loading="lazy"` дозволяє браузеру відкласти завантаження зображення до наближення до видимої області.

`toLocaleString('uk-UA')` форматує число за українськими правилами: наприклад, `6500` відображається як `6 500`. Значення ціни в JSON залишається числом.

Щоб додати меблі, достатньо додати запис із новим унікальним `id` до `products` та зображення до `public/images`. Компонент змінювати не потрібно.

## 8. Зображення

Зображення у форматі SVG зберігаються в `public/images`. Це прості локальні ілюстрації столу, стільця та шафи.

Шлях `/images/table.svg` починається від кореня сервера. Папка `public` у URL не пишеться: Vite віддає її вміст як статичні файли. Це відповідає принципу розміщення зображень із методички.

## 9. Footer

Футер отримує дані з `data.footer`. Вираз `'mailto:' + data.footer.email` утворює поштове посилання. У навчальному прикладі адреса демонстраційна, а не робоча пошта компанії.

Соціальні мережі виводяться через `map`, аналогічно до меню. `target="_blank"` відкриває посилання в новій вкладці; `rel="noreferrer"` не передає адресу вихідної сторінки та забезпечує відокремлення нової вкладки від початкової.

Оскільки реальних профілів компанії немає, посилання ведуть на головні сторінки Instagram і Facebook. Футер прямо позначає сайт як навчальний.

## 10. Адаптивність

`.container` обмежує ширину сторінки до 1100 px, залишаючи відступи на вузькому екрані. `box-sizing: border-box` включає внутрішні відступи та рамку в задані розміри елемента.

Для каталогу використано CSS Grid:

```css
.products {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 24px;
}
```

`repeat(3, 1fr)` створює три однакові колонки. `gap` задає проміжки між картками.

Медіазапити змінюють розташування залежно від ширини вікна:

- понад 800 px — три колонки товарів;
- від 561 до 800 px — дві колонки;
- до 560 px включно — одна колонка, блок про виробника теж стає одноколонковим, а шапка й футер розташовуються вертикально.

`flex-wrap: wrap` дозволяє пунктам меню переноситися. Метатег `viewport` у HTML потрібен для правильного масштабу сторінки на мобільних пристроях.

## 11. Чому реалізація відрізняється від методички

| У прикладі | У цій роботі | Причина |
| --- | --- | --- |
| Кав’ярня, страви, компонент `Dishes` | Виробник меблів, товари, компонент `Products` | Відповідає варіанту 6 |
| Create React App | Vite | Інший інструмент запуску і збірки; бібліотека React та принцип компонентів ті самі |
| Дані розділено між JSON-файлами | Один `data.json` із розділами | Для невеликої сторінки простіше редагувати один файл |
| Слайдер із таймером | Одна ілюстрація в блоці про виробника | Слайдер є деталлю прикладу, а не обов’язковим пунктом завдання |
| Окремі CSS-файли компонентів | Один `style.css` | Стилів мало, їх зручно тримати разом |

Vite наведений в [офіційній документації React](https://react.dev/learn/build-a-react-app-from-scratch) як інструмент для створення React-застосунку з нуля. Команду `npm start` збережено, як у методичці: у нашому `package.json` вона запускає Vite.

У таблиці методички згадується Angular, але тема, команди та приклади цієї роботи стосуються React. Тут реалізовано саме React.

Стан `useState`, ефекти `useEffect`, класи та запити до JSONBin тут не потрібні: дані статичні, а дії користувача — звичайні переходи за посиланнями. Вимоги першої самостійної про базовий клас і хмарний запит не переносяться автоматично на другу.
